## Endpoints
All under `/templates` (global) or `/communities/{id}/templates` (community-scoped), registered in `backend/app/routers/{templates,communities}.py`. All require Bearer auth.
- `POST /templates` — multipart/form-data: `image` (file, required), `name` (Form, required, 1–100 chars), `community_id` (Form, optional UUID — **Phase 6**). Omitted/`None` → global template, anyone can upload. Provided → `services/communities.py::require_active_membership` gates it: `404` if the community doesn't exist, `403` if the caller isn't an active member. → `201` `TemplateOut`. Same upload validation as before (content-type/empty/10MB, via shared `services/media.py`).
- `GET /templates?cursor=&limit=` — keyset-paginated, global library **only** (`WHERE community_id IS NULL`, added in Phase 6 — community templates never leak into this list, for any user, member or not). `limit` 1–50 (default 20 on backend; frontend requests 30). → `200` `TemplatePage`.
- `GET /communities/{community_id}/templates?cursor=&limit=` — **Phase 6**: that community's private templates. Gated by `require_active_membership` — **always member-only, with no open-community carve-out**, unlike [[communities]]'s member-*list* rule (which does let non-members read an open community's member list). Registered in `routers/communities.py` (path-based grouping, matching how [[meme-feed]]'s reactions/comments live under `routers/memes.py` despite being separate models). → `200` `TemplatePage`, `403`/`404` as above.

`TemplateOut` = `{id, uploader: UserOut, community_id: UUID | null, name, image_url, created_at}`.

## Business rules
- **No server-side overlay storage.** Text overlay position/content is never sent to or stored by the backend. The client composites (flattens) the base image + top/bottom text into a single bitmap in-app (`react-native-view-shot`), then uploads that flattened image through the **existing, unchanged** `POST /memes` endpoint from [[meme-feed]] — same as a plain image post. This is why the preview-vs-published exit test is trivially pixel-exact: the preview *is* the exact file that gets published, not a re-render. Keeps `Meme`'s schema untouched and avoids a second creation code path.
- Any authenticated user can upload a template to the global library. Uploading *to a community* requires active membership in that community — checked at upload time, not just at read time. Templates are read-only once created — no edit/delete endpoint (not in scope).
- **Community templates are private regardless of the community's `open`/`invite_only` privacy setting** (Project_Requirements §3: "visible and usable only by members... not shown in the public/global library, not usable by non-members" — no exception carved out for open communities, unlike the Phase 5 member-list rule). Don't accidentally relax this if extending community-scoped features later — check [[communities]]'s memory note on the discovery-vs-content-visibility split before assuming a Phase-5-style open-community exception applies.

- `services/templates.ts` (API calls) + `services/useTemplates.ts` (`useTemplates`/`useCommunityTemplates` infinite queries, `useCreateTemplateMutation` — **Phase 6**: takes an optional `communityId`, invalidates the matching query key — community-scoped cache when set, global otherwise) — same shape as [[meme-feed]]'s `memes.ts`/`useMemes.ts`.
- **`utils/multipartImage.ts::appendImageToFormData`** — extracted from `memes.ts` (2nd consumer: `templates.ts`) — the RN-native-vs-web `{uri,name,type}` vs. real-`Blob` multipart gotcha from [[meme-feed]] now lives in one place.
- `features/creator/CreatorScreen.tsx` — replaces [[meme-feed]]'s old minimal `NewPostScreen` at the same `/new-post` route (memory note in meme-feed.md flagged this as the expected outcome). Flow: pick own image (gallery) **or** pick a template (modal) → draggable top/bottom text overlay on an `OverlayCanvas` → **Preview** (captures the composed view to a real PNG via `react-native-view-shot`) → caption + audience selection (same Public/Friends toggle as before — Community audience is still Phase 7) → **Publish** (uploads the captured PNG via the unchanged `useCreateMemeMutation`).
- `features/creator/components/OverlayCanvas.tsx` — the `react-native-view-shot` capture target. Renders the base image (`contentFit="contain"`) plus two `DraggableText` overlays. **Must have `collapsable={false}`** on the captured root `View` — without it, Android's view flattening can make `captureRef` grab a blank/wrong frame (a real, easy-to-hit gotcha, not theoretical).
- `features/creator/components/DraggableText.tsx` — `react-native-gesture-handler`'s `Gesture.Pan()` + `react-native-reanimated` shared values for drag position; clamped to the canvas bounds using an *assumed* text-box footprint (160×44), not measured text width — acceptable approximation since only the drag handle needs to stay reachable, not pixel-exact edge clamping.
- `features/creator/components/TemplatePickerModal.tsx` — full-screen `Modal`. **Phase 6**: a horizontal scope-tab row ("Global" + one tab per community from `useMyCommunities()`) switches which grid renders — `GlobalTemplates` (`useTemplates`) or `CommunityTemplates` (`useCommunityTemplates(communityId)`), two tiny wrapper components in the same file (not extracted further — each is a 1-hook wrapper around the shared `TemplateGrid` presentational component). The "+" upload form is shared across scopes; submit passes `communityId` only when a community tab is active. This is where "submit new templates either to the global library or to a specific community's private library" (Project_Requirements §5) lives.
- `features/creator/components/TemplateGrid.tsx` — **Phase 6**: extracted presentational 3-column `FlatList` grid (props: items/loading/pagination/onSelect/emptyMessage), shared by both `GlobalTemplates` and `CommunityTemplates` so the two scopes don't duplicate the same JSX — each scope wrapper only differs in which query hook it calls (can't conditionally call `useTemplates` vs. `useCommunityTemplates` in one component per Rules of Hooks, hence two thin wrapper components instead of a branch).
- **`GestureHandlerRootView` added to `app/_layout.tsx`**, wrapping the whole app — required once by `react-native-gesture-handler` for any `GestureDetector` to work; this is the first feature in the codebase to use gesture-handler, so it wasn't there before.
- No new Redux state — the creator draft (base image, overlay text, captured URI) is local `useState`/`useForm` state inside `CreatorScreen`, consistent with "promote to Redux only on 2nd cross-component consumer."

## Gotchas
- **Orphaned `uvicorn --reload` worker survives killing its parent (Windows)**: uvicorn's `--reload` runs a reloader process that spawns the actual server as a child via `multiprocessing`. On Windows, killing the reloader (parent) does **not** cascade to the child — the child stays bound to the port and keeps serving whatever code was loaded when it started, silently. Hit this after adding the `/templates` router: the running dev server had been started before Phase 4 existed, WatchFiles triggered a reload on an unrelated file change, but the orphaned old worker kept answering requests, so `/templates` 404'd even though the code was correct and tests passed. Fix: find *both* PIDs (`Get-CimInstance Win32_Process -Filter "Name='python.exe'" | Where CommandLine -like '*uvicorn*' -or '*multiprocessing.spawn*'`), kill both, then start fresh. If routes seem to "disappear" or a new endpoint 404s despite correct code, check for this before assuming a code bug.
- `react-native-view-shot` was not previously a dependency — added via `npx expo install react-native-view-shot` (SDK-57-compatible version resolved: `5.1.0`). Native capture is solid on iOS/Android; RN Web capture support is weaker/best-effort, but web is not this app's target platform (Android APK first, per `frontend/CLAUDE.md`) — only `tsc`/`expo export --platform web` need to stay clean, not a fully working web capture.
- Running `expo lint` for the first time in this repo bootstrapped ESLint + `eslint-config-expo` as new devDependencies and created `frontend/eslint.config.js` (Expo CLI auto-installs on first run since no config existed before). Flagged here since it's a tooling-only side effect, not application code — one pre-existing-pattern warning surfaced (React Compiler flags `react-hook-form`'s `watch()` as unmemoizable; harmless, same pattern was already in the old `NewPostScreen`).
