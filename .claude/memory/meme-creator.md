## Endpoints
All under `/templates` (global) or `/communities/{id}/templates` (community-scoped), registered in `backend/app/routers/{templates,communities}.py`. All require Bearer auth.
- `POST /templates` — multipart/form-data: `image` (file) **or** `image_public_id` (Roadmap_Scaling.md A4 direct-to-Cloudinary flow — confirm the `public_id` from `POST /media/upload-signature` first), mutually exclusive, exactly one required; `name` (Form, required, 1–100 chars), `community_id` (Form, optional UUID — **Phase 6**). Omitted/`None` → global template, anyone can upload. Provided → `services/communities.py::require_active_membership` gates it: `404` if the community doesn't exist, `403` if the caller isn't an active member. → `201` `TemplateOut`. Same upload validation as before (content-type/empty/10MB, via shared `services/media.py`).
- `GET /templates?cursor=&limit=` — keyset-paginated, global library **only** (`WHERE community_id IS NULL`, added in Phase 6 — community templates never leak into this list, for any user, member or not). `limit` 1–50 (default 20 on backend; frontend requests 30). → `200` `TemplatePage`.
- `GET /communities/{community_id}/templates?cursor=&limit=` — **Phase 6**: that community's private templates. Gated by `require_active_membership` — **always member-only, with no open-community carve-out**, unlike [[communities]]'s member-*list* rule (which does let non-members read an open community's member list). Registered in `routers/communities.py` (path-based grouping, matching how [[meme-feed]]'s reactions/comments live under `routers/memes.py` despite being separate models). → `200` `TemplatePage`, `403`/`404` as above.

`TemplateOut` = `{id, uploader: UserOut, community_id: UUID | null, name, image_url, created_at}`.

## Business rules
- **No server-side overlay storage.** Text overlay position/content is never sent to or stored by the backend. The client composites (flattens) the base image + top/bottom text into a single bitmap in-app (**now via Skia `drawAsImage`, previously `react-native-view-shot`**), then uploads that flattened image through the **existing, unchanged** `POST /memes` endpoint from [[meme-feed]] — same as a plain image post. Preview-vs-published stays pixel-exact: preview and export render the **same `MemeScene` element tree** (one on the on-screen `<Canvas>`, one in an offscreen surface), and the exported PNG *is* the file published. Keeps `Meme`'s schema untouched, avoids a second creation code path, and unlike view-shot the export is a deterministic **1080²** (`EXPORT_SIZE`) regardless of device pixel density.
- Any authenticated user can upload a template to the global library. Uploading *to a community* requires active membership in that community — checked at upload time, not just at read time. Templates are read-only once created — no edit/delete endpoint (not in scope).
- **Community templates are private regardless of the community's `open`/`invite_only` privacy setting** (Project_Requirements §3: "visible and usable only by members... not shown in the public/global library, not usable by non-members" — no exception carved out for open communities, unlike the Phase 5 member-list rule). Don't accidentally relax this if extending community-scoped features later — check [[communities]]'s memory note on the discovery-vs-content-visibility split before assuming a Phase-5-style open-community exception applies.

## Frontend integration notes
- `services/templates.ts` (API calls) + `services/useTemplates.ts` (`useTemplates`/`useCommunityTemplates` infinite queries, `useCreateTemplateMutation` — **Phase 6**: takes an optional `communityId`, invalidates the matching query key — community-scoped cache when set, global otherwise) — same shape as [[meme-feed]]'s `memes.ts`/`useMemes.ts`.
- **`utils/multipartImage.ts::appendImageToFormData`** — extracted from `memes.ts` (2nd consumer: `templates.ts`) — the RN-native-vs-web `{uri,name,type}` vs. real-`Blob` multipart gotcha from [[meme-feed]] now lives in one place.
- `features/creator/CreatorScreen.tsx` — replaces [[meme-feed]]'s old minimal `NewPostScreen` at the same `/new-post` route. Flow: pick own image (gallery) **or** template (modal) → **＋ Text / 😊 Sticker / 🖼 Image** add layers, tap one to select → `LayerInspector` restyles it + drag/pinch/rotate on the Skia `EditorCanvas` + undo/redo → **Preview** (`editorRef.current.export()` flattens to a 1080² PNG) → caption + audience (Public/Friends) → **Publish** (`useCreateMemeMutation`). Resets the draft on mount and after publish. AI-caption context is built from all *text* layers' text joined. **"Image" adds a layer on top; "Upload from gallery" on the start screen sets the background — two different things.**
- `features/creator/document.ts` — the serializable `MemeDocument` = base image URI + **`canvas: {aspectId, fit, bg}`** + `Layer[]` (render order, last = topmost) + `selectedId`. **`Layer` is a discriminated union `TextLayer | ImageLayer`**; both extend a `BaseLayer` of `{id, pos (normalized center), scale (multiplier), rotation (radians)}` — the transform/selection system operates on those common fields generically. `TextLayer` adds text + `TextStyleSpec`; `ImageLayer` adds `uri` (aspect derived from the decoded image, not stored). **Geometry is normalized but NOT square-relative: `pos.x` is a fraction of canvas WIDTH, `pos.y` of HEIGHT; sizes/fonts base on width.** Export size = `canvasPixels(aspectId, EXPORT_MAX_SIDE=1080)` (longer side 1080). Holds `ASPECT_PRESETS`/`aspectRatio()`/`canvasPixels()`/`CanvasPx`, option lists (`FONT_OPTIONS`/`COLOR_SWATCHES`/`STROKE_WIDTH_OPTIONS`/`EMOJI_STICKERS`), `IMAGE_BASE_FRACTION`, factories (`createTextLayer`/`createImageLayer`/`createEmojiLayer`/`cloneLayer`), `isTextLayer` guard, and pure helpers (`clamp01`/`clampScale`/`alignedCenterX`/`getSelectedLayer`/`resolveFontFamilies`) — deliberately **Skia-free**, unit-tested in Node. An **emoji sticker is a `TextLayer`** (createEmojiLayer: emoji text, `strokeWidthFraction:0`, `scale:2`, plain family for the device color-emoji font).
- `features/creator/skiaMeme.tsx` — the Skia rendering core. Threads a **`CanvasPx {w,h}`** (not a single square `size`): `buildMemeLayers(doc, canvas, images)` bases text fonts / box widths / image widths on `canvas.w`; `staticLayerTransform`/`layerBBox` place x by `canvas.w` and y by `canvas.h`. Returns a generalized `BuiltLayer` per renderable layer: text → fill(+outline) `SkParagraph`s (stroke-then-fill = Impact look); image → the cached `SkImage` sized `canvas.w·IMAGE_BASE_FRACTION·scale` wide (height from the image's own aspect). `MemeScene` (single element tree for both the live `<Canvas>` and `exportMeme`'s `drawAsImage`) draws `<Fill color={bg}>` + base `<Image fit={fit}>` (contain letterboxes, cover center-crops) + layers + the selection rect for `selectedId` (null for export). `exportMeme(doc,image,images)` computes its own `canvasPixels(...,EXPORT_MAX_SIDE)`, encodes PNG, writes via **`expo-file-system` new OO API** (`new File(Paths.cache,…)` → `create()` → `write(bytes)` → `file.uri`).
- `features/creator/components/EditorCanvas.tsx` — `forwardRef` exposing `{ export() }`. **Measures the canvas `{w,h}` from an `aspectRatio`-set container `onLayout`** and threads it everywhere (pan normalizes translationX by w, translationY by h). Base image via Skia `useImage`. **Image layers are decoded imperatively into a `uri→SkImage` cache** (`Skia.Data.fromURI(uri)` → `Skia.Image.MakeImageFromEncoded`) in a `useEffect` keyed on the set of image uris — NOT `useImage` in a loop (Rules of Hooks) and NOT lazily inside the scene (a lazily-loaded image would be missing from the offscreen export snapshot). `export()` awaits any not-yet-decoded layer images before flattening. **Interaction model: tap to select (oriented-bbox hit test, topmost wins), then pan/pinch/rotate manipulate the SELECTED layer** (decoupling select from transform avoids a mid-gesture rebind glitch). Only ONE `useDerivedValue` (for the single selected layer) → no hooks-in-a-loop; unselected layers use static transforms. **Flicker-free commit**: the selected layer's transform is mirrored into *absolute* shared values synced from the doc; gestures commit the absolute value on release; the on-screen transform always reads the same absolute value the reducer stores (never base+delta). Live pinch scales by `liveScale/builtScale` (visual) until release rebuilds at the new size.
- `features/creator/components/LayerInspector.tsx` (was `TextInspector`) — contextual panel for the selected layer; **branches on kind**: text layers get the full styling child `TextStyleControls` (text field + font chips + fill/outline color swatches + outline-width + L/C/R align + shadow), image layers get just a hint. Both get the A−/A+ size stepper (`setSelectedScale`) and the layer actions (duplicate / to-front / to-back / delete / done). Swatch colors use inline `style` (dynamic palette Tailwind can't express); else NativeWind.
- `features/creator/components/StickerPickerModal.tsx` — full-screen `Modal` with a curated `EMOJI_STICKERS` grid (bounded → `.map` in a ScrollView is fine); `onSelect(emoji)` → `addEmojiLayer`.
- `features/creator/components/CanvasBar.tsx` — canvas controls above the editor (edit mode only): `ASPECT_PRESETS` chips, Fit/Fill toggle, and (when Fit) letterbox-color swatches → `updateCanvas(...)`. The captured-preview `<Image>` in `CreatorScreen` uses `aspectRatio(doc.canvas.aspectId)` so the preview frame matches the exported PNG.
- `features/creator/components/TemplatePickerModal.tsx` — full-screen `Modal`. **Phase 6**: a horizontal scope-tab row ("Global" + one tab per community from `useMyCommunities()`) switches which grid renders — `GlobalTemplates` (`useTemplates`) or `CommunityTemplates` (`useCommunityTemplates(communityId)`), two tiny wrapper components in the same file (not extracted further — each is a 1-hook wrapper around the shared `TemplateGrid` presentational component). The "+" upload form is shared across scopes; submit passes `communityId` only when a community tab is active. This is where "submit new templates either to the global library or to a specific community's private library" (Project_Requirements §5) lives.
- `features/creator/components/TemplateGrid.tsx` — **Phase 6**: extracted presentational 3-column `FlatList` grid (props: items/loading/pagination/onSelect/emptyMessage), shared by both `GlobalTemplates` and `CommunityTemplates` so the two scopes don't duplicate the same JSX — each scope wrapper only differs in which query hook it calls (can't conditionally call `useTemplates` vs. `useCommunityTemplates` in one component per Rules of Hooks, hence two thin wrapper components instead of a branch).
- **`GestureHandlerRootView` added to `app/_layout.tsx`**, wrapping the whole app — required once by `react-native-gesture-handler` for any `GestureDetector` to work; this is the first feature in the codebase to use gesture-handler, so it wasn't there before.
- **Redux `creatorDraftSlice`** (`store/creatorDraftSlice.ts`) owns the editable draft as a **past/present/future** undo/redo stack (bounded 50; a document is tiny JSON). Actions: `setBaseImage`, `updateCanvas` (partial `{aspectId,fit,bg}` merge, undoable), `addTextLayer`/`addEmojiLayer`/`addImageLayer`/`duplicateSelected`/`deleteSelected`/`reorderSelected`, `selectLayer`, `setSelectedText`, `updateSelectedStyle`, and **absolute** transform setters `setSelectedPosition`/`setSelectedScale`/`setSelectedRotation` (absolute, not relative — that's what makes the live-gesture commit flicker-free, see EditorCanvas). `setSelectedText`/`updateSelectedStyle` are **text-only** (guarded `kind === 'text'`, no-ops on image layers); `duplicateSelected` uses `cloneLayer` so it works for any kind; transform/reorder/delete are kind-agnostic. Selected-layer edits operate on `selectedId`; the gesture worklet only reports final absolute values via `runOnJS`, so no geometry crosses the JS boundary mid-drag. History recorded for structural/style/transform-commit edits; **not** for text typing or selection. `resetDraft` clears it. The RHF form owns **only** caption + audiences (`schemas.ts`); layer data lives entirely in the slice.

## Gotchas
- **A seed/import script writing to its own table ≠ writing to the app's table (real bug, hit 2026-07-26).** `scripts/import_imgflip.py` (one-off, not part of the FastAPI app) pulls 100 templates from the Imgflip API, uploads to Cloudinary, and originally stored metadata in a table it created itself (`imgflip_templates`) — that table is **not** what `GET /templates`/`services/templates.py` reads (that's the `templates` table backing the `Template` model). Result: Cloudinary had 100 images and Postgres had 100 rows, but the app's template picker showed none — the data existed, just in a disconnected table. Fixed by adding `sync_to_templates()` (copies any `imgflip_templates` cache row missing from `templates`, matched by `image_public_id`, no re-download/re-upload needed) plus a required `TEMPLATE_UPLOADER_EMAIL` env var (looks up an existing user by email to attribute the templates to, global/`community_id NULL`) and a `--sync-only` flag to resync without re-hitting Imgflip/Cloudinary. Backfilled the existing 100 via `TEMPLATE_UPLOADER_EMAIL=<email> python scripts/import_imgflip.py --sync-only`. **Lesson: any future one-off import/seed script must insert into the actual production table the app queries — a script-local cache/staging table is fine for dedup, but always sync from it into the real table in the same run, don't let it silently substitute for the real table.**
- **Orphaned `uvicorn --reload` worker survives killing its parent (Windows)**: uvicorn's `--reload` runs a reloader process that spawns the actual server as a child via `multiprocessing`. On Windows, killing the reloader (parent) does **not** cascade to the child — the child stays bound to the port and keeps serving whatever code was loaded when it started, silently. Hit this after adding the `/templates` router: the running dev server had been started before Phase 4 existed, WatchFiles triggered a reload on an unrelated file change, but the orphaned old worker kept answering requests, so `/templates` 404'd even though the code was correct and tests passed. Fix: find *both* PIDs (`Get-CimInstance Win32_Process -Filter "Name='python.exe'" | Where CommandLine -like '*uvicorn*' -or '*multiprocessing.spawn*'`), kill both, then start fresh. If routes seem to "disappear" or a new endpoint 404s despite correct code, check for this before assuming a code bug.
- **Skia is a native module → a Metro reload is NOT enough.** `@shopify/react-native-skia` (2.6.2, `npx expo install`) ships native code, and this project is managed/CNG (no `android/` dir, no `eas.json`). The current dev-client binary does not contain Skia, so after this change the app will **red-screen with "native module not found" until the dev client is rebuilt** — `npx expo run:android` (prebuild + gradle) or an EAS dev build. Per [[feedback_dev_server_restart]], don't call the editor "testable" on a plain `expo start`. No app config plugin was required for SDK 57 (Skia autolinks); only the rebuild.
- `react-native-view-shot` (5.1.0) is **no longer used by the creator** (Skia `drawAsImage` replaced it). Left in `package.json` for now — remove only after confirming nothing else imports it (grep: no other consumers as of this change, so it's safe to drop).
- `expo-file-system` SDK 57 uses the **new OO API** (`File`/`Directory`/`Paths`); `writeAsStringAsync`/`FileSystem.cacheDirectory` are legacy (`expo-file-system/legacy`). Export writes bytes with `file.write(uint8Array)` after `file.create()` — creating first avoids a write-to-nonexistent-file throw.
- **Immer history snapshots must use `current()` (real bug, caught by the new undo test).** In an RTK/Immer reducer, `state.past.push(state.present)` pushes a *live draft reference*; a later `state.present.x = …` in the same reducer then mutates the very object you "snapshotted," so the past entry aliases the mutated state and **undo can't revert**. `creatorDraftSlice`'s `recordHistory` (and undo/redo) snapshot with `current(state.present)` to detach a plain copy. Applies to any future Immer-based history stack.
- **Jest for a slice that imports Redux Toolkit needs an extended `transformIgnorePatterns`.** `jest-expo`'s default ignores `node_modules`, but `@reduxjs/toolkit` pulls in `immer`'s ESM build (`immer.legacy-esm.js`) → "Unexpected token 'export'". `jest.config.js` re-declares jest-expo's allow-list plus `@reduxjs/toolkit|immer|redux|reselect|redux-thunk`. Test files import globals from `@jest/globals` (ships with jest) so no `@types/jest` dep is needed and `tsc` (which includes `**/*.test.ts`) stays happy.
- Running `expo lint` for the first time in this repo bootstrapped ESLint + `eslint-config-expo` as new devDependencies and created `frontend/eslint.config.js` (Expo CLI auto-installs on first run since no config existed before). Flagged here since it's a tooling-only side effect, not application code — one pre-existing-pattern warning surfaced (React Compiler flags `react-hook-form`'s `watch()` as unmemoizable; harmless, same pattern was already in the old `NewPostScreen`).
- **Image *layers* can't use `useImage` and can't load lazily.** Skia's `useImage` is a hook → can't call it per-layer over a dynamic array (Rules of Hooks), and a `<Image>` that decodes lazily inside the scene would be **missing from `drawAsImage`'s export snapshot** (the snapshot is taken before the async decode finishes). Solution (EditorCanvas): decode imperatively via `Skia.Data.fromURI(uri)` → `Skia.Image.MakeImageFromEncoded(data)` into a `uri→SkImage` cache used by both preview and export, and `export()` awaits any missing decodes first. The base background image still uses `useImage` (single, not in a loop). When adding *any* new async Skia resource to the scene, pre-decode it — don't rely on a hook resolving before the snapshot.
